## Project Overview

btrack is a Wails v2 desktop application combining a Go backend with a React frontend. Wails embeds web technologies into native desktop applications using Go instead of Node.js/Electron.

## Key Commands

### Development
```bash
# Run in live development mode with hot reload
wails dev
```
Starts both Go backend and Vite dev server with hot reload. Frontend accessible at dev server URL. Go methods available at http://localhost:34115 for browser-based development.

### Building
```bash
# Build production binary for current platform
wails build
```
Compiles frontend, embeds it into Go binary, and creates distributable application.

### Frontend Commands
```bash
# From frontend/ directory
npm install          # Install dependencies
npm run dev          # Run Vite dev server independently
npm run build        # Build frontend assets
```

## Architecture

### Go Backend Structure
- **main.go**: Application entry point
  - Embeds compiled frontend assets from `frontend/dist` via `//go:embed all:frontend/dist`
  - Creates App instance and binds it to frontend via `Bind: []interface{}{app}`
  - Configures window (1024x768) and styling
- **app.go**: Contains App struct with methods exposed to frontend
  - All public (capitalized) methods are automatically callable from JavaScript
  - The `startup` method receives runtime context when app initializes
- **go.mod**: Uses Go 1.23 and Wails v2.11.0

### Frontend Structure
- **Location**: `frontend/` directory
- **Stack**: React 18 + Vite
- **Bindings**: `frontend/wailsjs/` contains auto-generated TypeScript/JavaScript bindings
  - These bindings provide typed function calls to Go methods (e.g., `Greet` from `wailsjs/go/main/App`)
  - **CRITICAL**: Never manually edit files in `wailsjs/` - they are regenerated by Wails
- **Entry Point**: `frontend/src/main.jsx` renders the React app
- **Main Component**: `frontend/src/App.jsx` demonstrates calling Go methods via bindings

### Build System
- **frontend/dist**: Compiled frontend assets embedded into Go binary at build time
- **build/**: Platform-specific configurations (darwin/, windows/) and app icon
- **wails.json**: Project configuration including frontend build commands

## Development Workflow

### Adding New Go Methods
1. Add public (capitalized) methods to the `App` struct in `app.go`
2. Methods must be exported to be accessible from frontend
3. Run `wails dev` - bindings in `frontend/wailsjs/` auto-regenerate
4. Import and use from `frontend/wailsjs/go/main/App` in React components

Example:
```go
// In app.go
func (a *App) MyNewMethod(param string) string {
    return "result: " + param
}
```

```javascript
// In React component
import {MyNewMethod} from "../wailsjs/go/main/App";
MyNewMethod("test").then(result => console.log(result));
```

### Binding Multiple Structs
To expose methods from multiple Go structs, add them to the `Bind` slice in `main.go`:
```go
Bind: []interface{}{
    app,
    anotherStruct,
},
```

### Frontend Development
- Edit React components in `frontend/src/`
- Changes hot reload automatically during `wails dev`
- Use generated bindings from `wailsjs/` to call Go methods
- Frontend dependencies managed via `frontend/package.json`

## Important Constraints

1. **Never Edit Generated Bindings**: Files in `frontend/wailsjs/` are auto-generated by Wails. Any manual edits will be overwritten.

2. **Go Method Visibility**: Only exported (capitalized) methods in bound structs are accessible from frontend.

3. **Frontend Asset Embedding**: Frontend assets are embedded at build time via `//go:embed`. Changes to `frontend/src/` require rebuild or `wails dev` to take effect in production builds.

4. **Wails Configuration**: Project metadata and build commands configured in `wails.json`. Frontend build commands: `npm install`, `npm run build`, `npm run dev`.
